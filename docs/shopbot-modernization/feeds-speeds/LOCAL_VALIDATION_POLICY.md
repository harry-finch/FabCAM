# Sorbonne local validation policy — revision 1

Policy ID: sorbonne-local-validation-1. Established in FS3.8 for later FS4 use.
No physical FS3.8 qualification is claimed. This policy is an operator review
workflow, not a general safety certification or a numerical cutting guarantee.

| Authoring state | Required evidence | Recommendation eligibility |
| --- | --- | --- |
| Draft | Reliable available context and positive captured values; no physical-use claim required | Never; stored as inactive theoretical authoring record |
| Tested | Actual physical use on recorded machine/material/tool/operation, valid date, known entry/engagement, actual resolved values, operator attests no critical failure | Existing exact Tested preset tier, in recorded scope/mode only |
| Validated | Previously Tested; later explicit review with notes and policy/date, attesting acceptable finish and machining behavior, no overheating/chatter/overload, suitability for normal lab use | Existing exact Validated tier, in recorded scope/mode only |

Operator and job references are optional. Detailed notes should describe relevant
finish/dimensions, heat, vibration/chatter, chip quality, hold-down and tool condition
when known. Do not claim measured values that were not measured. No arbitrary
minimum test count, numeric tolerance or broad material equivalence is imposed.
FS4 can strengthen the policy through a new documented policy revision and review;
existing records are not automatically promoted by a future policy.

Save offers Draft/Tested. Settings promotion requires review notes and a deliberate
confirmation that all criteria apply to this exact preset. Imported ReferenceData
and theoretical values never become Tested just by import. Software validates
attestation structure and context, not whether the operator really cut material.
SOFTWARE ONLY synthetic test attestations validate program behavior exclusively.

A new cut/update replaces current values only with explicit duplicate choice,
preserves previous evidence in history, and starts at Draft/Tested; later Validated
review is required again. Disable/delete excludes a record without erasing history.
Human approval of FS3.8 is required before beginning FS4 machine trials.
